# MICROSERVICE.md Specification

**Version:** 1.0.0
**Status:** Stable
**File extension / name:** `MICROSERVICE.md`, placed at the root of a microservice's repository.

## 1. Introduction

MICROSERVICE.md is a single-file, human-readable, AI-parseable documentation
standard for a microservice. It captures the information a new engineer,
an on-call responder, or an AI coding agent needs to understand a service
without reading its source: what it's responsible for, how other systems
talk to it, what it owns, how it fails, and how it's operated.

The format is plain [CommonMark](https://commonmark.org/) Markdown. It uses
a fixed set of headings, tables, and `**Label:** value` lines so that the
document is both:

- **Readable** — it renders correctly on GitHub, GitLab, and any Markdown
  viewer with no special tooling.
- **Parseable** — every section has an unambiguous grammar (below), so
  tools can extract structured data from it and regenerate it losslessly.

## 2. Conformance language

The keywords **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY**
are used as defined in [RFC 2119](https://www.rfc-editor.org/rfc/rfc2119).

## 3. Design principles

1. **Optional by default.** Every section below the header is optional. A
   section (and its parent, if it would otherwise be empty) is omitted
   entirely when it has no content — an empty section is not written as an
   empty heading.
2. **One document, one service.** MICROSERVICE.md describes exactly one
   microservice. Systems composed of many services have one file per
   service.
3. **Lossless round-trip.** A conforming tool that generates a
   MICROSERVICE.md from structured data, and later re-parses that same
   file, MUST recover equivalent structured data. This is what makes the
   format safe to hand-edit: a human can edit the Markdown directly and a
   tool can re-sync it.
4. **Unknown content is preserved, not discarded.** Tools that
   programmatically update a MICROSERVICE.md MUST NOT delete headings,
   sections, or content they don't recognize. Extensions live safely
   alongside the standard sections (see §9).
5. **No secrets.** MICROSERVICE.md documents *where* secrets live (a
   secret store and its reference/URL) and *what* they're for — never the
   secret values themselves.

## 4. Document structure

A MICROSERVICE.md file is, top to bottom:

```
# <Service Name>
> <Mission statement>                     (optional)
**Bounded Context:** ...                  (optional metadata block)
**Team:** ... · <contact>
**On-call:** ...
---
## Responsibilities
## Interfaces
### REST API
### GraphQL Schema
### gRPC Proto
### Published Events
### Consumed Events
---
## Data & Dependencies
### Owned Data
### Sync Dependencies
### Async Dependencies
---
## Operations
### SLO / SLA
### Security
### Deployment
---
## Observability
### Logs
### Metrics
### Distributed Tracing
### Dashboards
### Alerts
---
## Architecture Patterns
### DDD Aggregates
### API Gateway
### Backend for Frontend (BFF)
### CQRS
### Sagas
### Materialized Views
---
## Runbook
---
## Architecture Decision Records
---
## Context Pack
---
_Generated by [Microservice.MD™](https://microservice.md) on <date> — ..._
```

A `---` (thematic break) separates each top-level (`##`) group from the
next, and appears **only** when at least one section in that group has
content. The four second-level groups — **Interfaces**, **Data &
Dependencies**, **Operations**, **Observability** — are themselves omitted
entirely if none of their subsections have content.

## 5. Header & metadata

```markdown
# checkout-service

> Owns the shopping cart lifecycle and coordinates checkout across payment,
> inventory, and shipping.

**Bounded Context:** Order Management
**Team:** Commerce Platform · #commerce-platform (Slack)
**On-call:** PagerDuty: commerce-platform-oncall

---
```

| Element | Required | Rule |
|---|---|---|
| `# <name>` | **MUST** | Exactly one H1, the service name. First line of the file. |
| `> <mission>` | MAY | A single blockquote line stating the service's purpose in one sentence. |
| `**Bounded Context:**` | MAY | The service's DDD bounded context. |
| `**Team:**` | MAY | Owning team, optionally followed by `· <contact>` (Slack channel, email, etc.). |
| `**On-call:**` | MAY | On-call routing (e.g. a PagerDuty schedule name). |

Metadata lines are written with a trailing double-space (a Markdown hard
line break) so they render as consecutive lines within one paragraph.

## 6. Sections reference

Each entry below gives: heading level and exact text, the body grammar, and
the field(s) it round-trips to. Headings are matched case-insensitively by
conforming tools but SHOULD be written exactly as shown.

### 6.1 `## Responsibilities`

A flat bullet list, one responsibility per line:

```markdown
## Responsibilities
- Owns the lifecycle of a shopping cart from creation to checkout
- Validates cart contents against current pricing and inventory
- Publishes `cart.checked_out` when checkout completes
```

### 6.2 `## Interfaces`

Parent heading for every way other systems talk to this service. Present
only if at least one child subsection is present.

#### `### REST API`

A table with columns **Method | Path | Description**. Method MUST be one
of `GET POST PUT PATCH DELETE HEAD OPTIONS` (case-insensitive on input,
written upper-case).

```markdown
### REST API
| Method | Path | Description |
| ------ | ---- | ------------ |
| GET | /carts/{id} | Fetch a cart by id |
| POST | /carts/{id}/items | Add an item to a cart |
```

#### `### GraphQL Schema`

A fenced ` ```graphql ` code block containing the SDL.

#### `### gRPC Proto`

A fenced ` ```protobuf ` code block containing the `.proto` definition.

#### `### Published Events`

A table with columns **Name | Schema | Broker**. `Schema` and `Broker` are
optional per row (may be left blank).

#### `### Consumed Events`

A table with columns **Name | Source | Broker**. `Source` names the
producing service; `Broker` is optional.

### 6.3 `## Data & Dependencies`

#### `### Owned Data`

A table with columns **Store | Type | Description**. `Type` MUST be one of
`postgres`, `mongo`, `redis`, `other`.

#### `### Sync Dependencies`

A table with canonical columns **Service | Type | Criticality | Reason |
Endpoints | Resilience**. Columns are located by header name, so a legacy
4-column table (`Service | Criticality | Reason | Resilience`) is still
valid to read.

| Column | Values |
|---|---|
| `Type` | `internal` \| `cloud` (defaults to `internal`) |
| `Criticality` | `hard` \| `soft` — **required** |
| `Endpoints` | comma-separated `METHOD /path` pairs the caller uses on the dependency |
| `Resilience` | comma-separated subset of `retry, circuit-breaker, timeout, bulkhead, fallback, rate-limit, cache` |

```markdown
### Sync Dependencies
| Service | Type | Criticality | Reason | Endpoints | Resilience |
| ------- | ---- | ------------ | ------ | --------- | ---------- |
| payments-service | internal | hard | Authorizes and captures payment | POST /charges | retry, circuit-breaker |
| aws-s3 | cloud | soft | Stores receipt PDFs | | timeout |
```

#### `### Async Dependencies`

A table with columns **Service | Event | Broker**, listing events this
service consumes and which service produces them.

### 6.4 `## Operations`

#### `### SLO / SLA`

A bullet list of `**Label:** value` lines, any subset of:
`**Availability:**`, `**Latency P99:**`, `**Error Budget:**`, `**SLA:**`.

#### `### Security`

A bullet list of `**Label:** value` lines:

| Label | Format |
|---|---|
| `**Authentication:**` | free text (e.g. `OAuth2 client-credentials`) |
| `**Authorization:**` | free text (e.g. `RBAC via scopes`) |
| `**Scopes:**` | comma-separated list |
| `**Secrets:**` | comma-separated list of secret *names*, never values |
| `**Secret store:**` | one of the labels in the table below, optionally followed by `(<url>)` |
| `**Handles PII:**` | literal `Yes` if the service processes personally identifiable information |

Secret store labels (value written → meaning):

| Written label | Meaning |
|---|---|
| `HashiCorp Vault` | `hashicorp-vault` |
| `AWS Secrets Manager` | `aws-secrets-manager` |
| `Azure Key Vault` | `azure-key-vault` |
| `GCP Secret Manager` | `gcp-secret-manager` |
| `Doppler` | `doppler` |
| `1Password` | `1password` |
| `Infisical` | `infisical` |
| `CyberArk Conjur` | `cyberark-conjur` |
| `Kubernetes Secrets` | `kubernetes-secrets` |
| `Bitwarden Secrets` | `bitwarden-secrets` |
| `Other` | `other` |

#### `### Deployment`

A bullet list of `**Label:** value` lines: `**Platform:**` (one of
`kubernetes`, `helm`, `railway`, `northflank`, `vercel`, `other`),
`**Replicas:**` (integer), `**CPU:**`, `**Memory:**`, `**Env Vars:**`
(comma-separated names — never values).

### 6.5 `## Observability`

Present only if the service defines any of logs, metrics, tracing,
dashboards, or alerts. Unlike other groups, `### Logs`, `### Metrics`, and
`### Distributed Tracing` are always written together as a unit once the
group is present.

#### `### Logs`

Free-text description of log format/destination, or the literal
`_No log configuration defined._` placeholder.

#### `### Metrics`

A table with columns **Metric | Description**, where `Metric` is an
inline-code metric name, or the literal `_No metrics defined._` placeholder.

#### `### Distributed Tracing`

One literal sentence: `Distributed tracing is **enabled**.` or
`Distributed tracing is **disabled**.`

#### `### Dashboards`

A bullet list of dashboard names/links. Omitted if empty.

#### `### Alerts`

A bullet list of alert names/descriptions. Omitted if empty.

### 6.6 `## Architecture Patterns`

Parent heading for optional architectural documentation. Present only if
at least one pattern below is defined.

#### `### DDD Aggregates`

One `####` block per aggregate:

```markdown
#### Cart
- **Root entity:** Cart
- **Entities:** CartItem (sku, quantity, unitPrice)
- **Value objects:** Money (amount, currency)
- **Invariants:**
  - A cart cannot contain a negative quantity
  - Total is always the sum of line items
- **References:** Customer, Promotion
- **Description:** The active shopping cart for one customer session.
```

`**Entities:**` and `**Value objects:**` use the format
`Name (prop1, prop2) · Name2 (prop1) · Name3` — items separated by ` · `,
each optionally followed by a parenthesized, comma-separated property list.
`**Invariants:**` is a nested bullet list. `**References:**` is a
comma-separated list of sibling aggregate names.

#### `### API Gateway`

A table with columns **Name | Host | Auth**.

#### `### Backend for Frontend (BFF)`

A table with columns **Channel | Framework | Deployment | URL**. `Channel`
MUST be one of `web`, `mobile`, `partner-api`, `admin-console`, `other`.

#### `### CQRS`

A table with columns **Role | Linked Service**. `Role` MUST be one of
`writer`, `reader`, `both`.

#### `### Sagas`

One `####` block per saga:

```markdown
#### CheckoutSaga
- **Type:** Orchestration
- **Trigger:** `cart.checkout_requested`
- **Happy path:** ReserveInventory → ChargePayment → ConfirmOrder → Ship
- **Compensating:** ReleaseInventory → RefundPayment → CancelOrder
- **States:** `pending` · `reserved` · `charged` · `confirmed` · `failed`
```

`**Type:**` is `Orchestration` or `Choreography` (`type` field:
`orchestration` \| `choreography`). `**Trigger:**` is an inline-code event
name. `**Happy path:**` and `**Compensating:**` are ordered steps joined
by ` → `. `**States:**` is inline-code state names joined by ` · `.

#### `### Materialized Views`

A table with columns **View | Source | Storage**.

### 6.7 `## Runbook`

Free-form Markdown: operational procedures, common failure modes,
diagnostic steps, escalation paths. No fixed grammar beyond being valid
Markdown — tools MUST treat it as opaque text.

### 6.8 `## Architecture Decision Records`

One `###` block per ADR:

```markdown
### ADR-003: Use event sourcing for the cart aggregate

**Status:** accepted

We chose event sourcing over CRUD persistence for the Cart aggregate
because checkout requires a full audit trail of cart mutations...
```

The heading MUST match `### <id>: <title>`. `**Status:**` MUST be one of
`proposed`, `accepted`, `deprecated`. Everything after the status line is
free-text rationale/content.

### 6.9 `## Context Pack`

Free-form Markdown intended for AI coding agents: a distilled summary of
the service's domain model, conventions, and gotchas that doesn't fit
elsewhere. Opaque text, like the Runbook.

### 6.10 Footer

Conforming generators SHOULD end the file with an attribution line
identifying the generating tool and generation date, e.g.:

```markdown
_Generated by [Microservice.MD™](https://microservice.md) on 2026-08-09 — MICROSERVICE.md™ is a lightweight, AI-ready documentation specification for microservice systems, created by [Koesion](https://microservice.md)._
```

This line is metadata about the document, not part of its content, and
tools MUST NOT parse it for service data.

| ADR status | `proposed`, `accepted`, `deprecated` |

## 8. Extensibility

A file may contain headings not defined in this spec (custom `##`/`###`
sections, extra metadata lines). Conforming tools:

- **MUST** preserve unrecognized headings and their content verbatim when
  programmatically updating the file.
- **MUST NOT** treat an unrecognized heading as an error.
- **SHOULD** place custom top-level sections after `## Context Pack` and
  before the footer, to keep the standard section order predictable for
  readers and tools.

Future minor versions of this spec add new optional sections or `**Label:**`
lines without breaking documents that don't use them. A major version bump
is required only for a change that breaks round-trip parsing of an
existing, valid v1 document.
